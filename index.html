📲 Install on Your Phone

MaxPlan works fully offline once installed. Add it to your home screen to open it like a native app — no browser chrome, no internet needed.

🍎 iPhone & iPad (Safari only)
1
Open the app URL in Safari — not Chrome or Firefox
2
Tap the Share button — the box with an arrow pointing up, at the bottom of the screen
3
Scroll down and tap "Add to Home Screen"
4
Tap "Add" in the top right corner
🤖 Android (Chrome)
1
Open the app URL in Chrome
2
Tap the three-dot menu (top right) and select "Install App" or "Add to Home Screen"
3
Tap "Install" to confirm
✓ Once installed, MaxPlan opens full-screen with no browser bar and works completely offline — even with no signal.

May Week 2 2026
Previous
  • Scanner buttons restored — all barcode scan buttons throughout the app stopped working in v1.4.4. The root cause was a JavaScript syntax error introduced when the WO Location scan button routing was added: the opening if (id && id.startsWith('__nr_')) { guard was accidentally deleted, leaving the __nr_ branch as unconditional top-level code with duplicate const declarations. In the scanner IIFE's strict mode this caused a SyntaxError, which prevented the entire IIFE from executing — meaning window.openScanner was never assigned and every scan button silently failed. Fixed by restoring the correct if guard

v1.4.5
May Week 2 2026
Previous
  • Update mechanism fully rebuilt — the Update button now reliably applies new versions. Three root causes were fixed:
    • Race condition — the update banner was shown as soon as version.json was fetched, but the new service worker may still be downloading. Tapping Update while it was still installing caused a fallback reload with the old SW still in control, serving the old cached page. Fix: doUpdate() now calls reg.update() to force a fresh SW check and waits up to 8 seconds for the new SW to reach the installed (waiting) state before sending SKIP_WAITING
    • sessionStorage not cleared — sessionStorage persists across location.reload() in the same browser tab. After a failed reload, the version check guard (vchk) was still set, so chkVer() returned early and the banner persisted. Fix: sessionStorage.removeItem('vchk') is called before every reload, and the controllerchange handler also clears it
    • No confirmation after update — after reload there was no check that the update succeeded. Fix: chkVer() now explicitly hides the banner when APP_VER matches version.json, confirming success
  • Update button shows "Updating…" while waiting for the new SW to install
  • All v1.4.4 features retained

v1.2.9
April Week 3 2026
Previous
  • Root cause identified and fixed: all versions from v1.2 through v1.2.8 used @zxing/library — the low-level ZXing core which is officially marked deprecated for browser use in its own source code. The correct package is @zxing/browser, a separate dedicated browser layer.
  • Live mode now uses decodeFromConstraints() — the documented continuous-callback API from @zxing/browser. ZXing manages the camera stream and decode loop internally. No manual frame capture, no canvas cropping required.
  • Photo mode now uses decodeFromImageElement() — reads directly from a DOM <img> element. This is the correct path for static image decoding.
  • Both live and photo modes use the same BrowserMultiFormatReader from @zxing/browser, built with TRY_HARDER hint and Code 128 format priority
  • Keeps the dual-mode UI from v1.2.8: live scan by default, with a toggle to Photo Mode as fallback
v1.2.8
April Week 2 2026
Previous
  • Dual-mode scanner: Live video (default) + Photo capture fallback, switchable via a toggle button in the scanner UI
  • Live mode: Returns to real-time camera decoding, but now uses a horizontal crop loop (aspect ratio 3.5:1) — Code 128 barcodes are wide and short, so cropping to a horizontal strip focuses the decoder on the barcode region rather than wasting processing on the full frame
  • The crop region maps directly to the on-screen scan window, so what you see in the frame is exactly what gets decoded
  • Runs at ~15fps via requestAnimationFrame to balance decode speed and battery life
  • Photo mode fallback: Available via the "Use Photo" button — uses native camera + decodeFromImageUrl() across 4 rotations (retained from v1.2.7)
  • Inspired by html5-qrcode's crop-region and aspect-ratio approach (learned from, not copied)
  • Recommended licensed scanners: Scandit (industry standard), Dynamsoft Barcode Reader (free dev tier), Zebra Browser Print
