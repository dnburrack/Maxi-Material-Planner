v1.2.9
April Week 2 2026
Previous
  • Root cause identified and fixed: all versions from v1.2 through v1.2.8 used @zxing/library — the low-level ZXing core which is officially marked deprecated for browser use in its own source code. The correct package is @zxing/browser, a separate dedicated browser layer.
  • Live mode now uses decodeFromConstraints() — the documented continuous-callback API from @zxing/browser. ZXing manages the camera stream and decode loop internally. No manual frame capture, no canvas cropping required.
  • Photo mode now uses decodeFromImageElement() — reads directly from a DOM <img> element. This is the correct path for static image decoding.
  • Both live and photo modes use the same BrowserMultiFormatReader from @zxing/browser, built with TRY_HARDER hint and Code 128 format priority
  • Keeps the dual-mode UI from v1.2.8: live scan by default, with a toggle to Photo Mode as fallback
v1.2.8
April Week 2 2026
Previous
  • Dual-mode scanner: Live video (default) + Photo capture fallback, switchable via a toggle button in the scanner UI
  • Live mode: Returns to real-time camera decoding, but now uses a horizontal crop loop (aspect ratio 3.5:1) — Code 128 barcodes are wide and short, so cropping to a horizontal strip focuses the decoder on the barcode region rather than wasting processing on the full frame
  • The crop region maps directly to the on-screen scan window, so what you see in the frame is exactly what gets decoded
  • Runs at ~15fps via requestAnimationFrame to balance decode speed and battery life
  • Photo mode fallback: Available via the "Use Photo" button — uses native camera + decodeFromImageUrl() across 4 rotations (retained from v1.2.7)
  • Inspired by html5-qrcode's crop-region and aspect-ratio approach (learned from, not copied)
  • Recommended licensed scanners: Scandit (industry standard), Dynamsoft Barcode Reader (free dev tier), Zebra Browser Print
v1.2.7
April Week 2 2026
Previous
  • Fixed root cause of decode failure in v1.2.5/v1.2.6: decodeFromCanvas() bypasses ZXing's internal image scaling and binarisation pipeline, causing it to silently fail on real photos from mobile cameras
  • Replaced with decodeFromImageUrl(blobURL) — ZXing's primary documented decode path: it creates its own HTMLImageElement, loads the image properly, draws it to an internal canvas at the correct size, then runs the full binarisation and barcode detection pipeline
  • For each rotation (0°, 90°, 270°, 180°), draws to a canvas, calls canvas.toBlob() to get a proper image file, then calls decodeFromImageUrl() — ensures ZXing processes a clean image at every orientation
  • All barcode formats retained: Code 128, Code 39, EAN-13, EAN-8, UPC-A, UPC-E, QR Code, Data Matrix, ITF, Codabar, PDF-417, Aztec
  • All other app features unchanged

v1.2.2
April Week 2 2026
Previous
  • Barcode scanner rebuilt using QuaggaJS — a purpose-built mobile barcode library that works on iOS Safari (14+) and all Android browsers
  • Fixed: previous pure-JS implementation failed to reliably decode Code 128 in real lighting conditions; QuaggaJS uses a proven computer-vision pipeline specifically tuned for 1D barcodes on mobile cameras
  • iOS compatibility: numOfWorkers is automatically set to 0 on iPhone/iPad (Safari's WKWebView does not support shared workers)
  • Requires 2 consistent reads of the same value before confirming — reduces false positives from partial frames
  • QuaggaJS is cached by the service worker on first load — scanner works fully offline after that
  • Scans only the middle 60% of the frame area for faster decoding on mobile hardware
  • All v1.2.1 features retained
v1.2.1
April Week 2 2026
Previous
  • Barcode scanner completely rebuilt as a pure JavaScript Code 128 decoder — zero external dependencies, zero browser APIs beyond the camera itself, works on every browser, 100% offline
  • Fixed: previous versions relied on BarcodeDetector (Chrome/Android and iOS 17+ only) which caused the "unsupported browser" error on most iPhones; the new decoder runs its own scan logic and works on all iOS and Android browsers
  • Scanner reads frames from the live video feed, converts each row to grayscale, applies adaptive thresholding, measures bar/space run widths, quantises to Code 128 module widths (1–4), and matches against the full 107-symbol ISO 15417 Code 128 table
  • Scans 40 horizontal rows per frame and requires 2 consistent reads before confirming a result — reduces false positives
  • Decodes Code A, Code B, and Code C start codes; verifies checksum before returning
  • All v1.2 features retained
